# Meridian Operating System Roadmap

This roadmap is subordinate to governing design and owner decisions. One bounded vertical slice must be completed and verified before the next begins.

| Phase | Outcome | Exit evidence |
|---|---|---|
| Audit | Reconciled authority, implementation, and gaps | Audit, decision record, one approved slice |
| Digital twin | Immutable observations and reproducible actual-state snapshots | Migration, API/service tests, provenance and stale-state browser checks |
| Simulation | Isolated 7/30/90/365-day scenarios | Deterministic scenario tests; no real-ledger writes |
| Constitution | Inspectable policy evaluation | Rule/evidence/assumption results and blocked-action tests |
| Proactive layer | Grouped meaningful events and weather states | Noise controls, freshness behavior, user-facing explanations |
| Evidence | Balance forensics and anomaly investigation | Evidence-linked explanations and privacy review |
| Agents | Specialized structured reasoning roles | Tool/authority matrix and adversarial tests |
| Operations | Consolidated approved interventions | Idempotency, uncertain-write readback, receipts |
| Builder | Sandboxed proposals for skills/UI/connectors | Tests, permission diff, explicit installation approval |
| Release | Owner-approved production deployment | Tested digest, live acceptance, rollback evidence |

Owner-gated items include policy activation, financial authority grants, credential changes, live external integration acceptance, production deployment, and installation of self-improvement proposals.
